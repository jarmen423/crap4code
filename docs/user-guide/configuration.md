# Configuration

The single source of truth is the repo-local `.crap4code.toml` file (sibling to your source directories). This makes behavior easy for humans and agents to audit in CI or loops. See `src/crap4code/core/config.py` (module docstring + `load_project_config` + `sample_config_text`) and root `README.md` "Config" section.

`crap4code init` materializes a heavily-commented canonical sample. The comments inside the generated file are the primary durable documentation for the coverage execution model and cross-platform shell realities — read them after running init.

## Top-Level Sections

- `[scan]` — global defaults (applies when a language section does not override).
- `[python]`, `[javascript]`, `[typescript]`, `[rust]` — per-language settings. A language is considered only if it is both enabled in config *and* present in the runtime registry (see `src/crap4code/languages/registry.py` for lazy loading).

### [scan]

```toml
[scan]
default_paths = ["src"]   # used when a language section has no "paths" and no CLI paths given
format = "table"          # "table" or "json"
threshold = 8.0           # CRAP threshold for exit code 2 (only measured scores are considered)
```

- `default_paths`: list of directories (relative to root or absolute). These are starting points for recursive discovery, **not** a list of every source file.
- See usage for CLI overrides (`paths...` positional, `--config`, `--format`, `--threshold`).

### Per-Language Sections (e.g. [python], [rust])

Each can contain:

- `enabled = true` (boolean; non-booleans are not coerced — see `config.py:_parse_enabled_value`).
- `paths = ["src", "tests"]` — list of directories (or files) to search. Overrides `[scan] default_paths` for this language.
- `coverage_command = "..."` — exact string executed via `subprocess.run(..., shell=True)` **only** when the command is present and `--report-only` is *not* used. See the long "COVERAGE COMMAND SHELL MODEL" comment block at the top of the file generated by init.
- `coverage_report = "coverage.xml"` or `"coverage/lcov.info"` — path to the report file (relative to root or absolute).
- `coverage_format = "coverage.py-xml"` or `"lcov"` — tells the loader which parser to use (see concepts for formats).
- `stale_artifacts = [".coverage", "coverage.xml", "htmlcov"]` — list of paths (files or dirs) to attempt to delete before running `coverage_command`. Cleanup is hardened and collects warnings instead of aborting (see `src/crap4code/core/coverage.py:cleanup_artifacts`).

Example from the canonical sample (excerpt; the real generated file has far more explanatory comments):

```toml
[python]
enabled = true
paths = ["src", "tests"]
coverage_command = "python -m pytest --cov=src --cov-report=xml:coverage.xml --cov-report=term-missing -q && python -m coverage xml -o coverage.xml"
coverage_report = "coverage.xml"
coverage_format = "coverage.py-xml"
stale_artifacts = [".coverage", "coverage.xml", "htmlcov"]

[rust]
enabled = true
paths = ["src"]
coverage_report = "coverage/lcov.info"
coverage_format = "lcov"
stale_artifacts = []
# Many Rust projects produce lcov via cargo-llvm-cov or tarpaulin as part of normal CI.
# Prefer running your project's own step once, then use crap4code --report-only.
```

## Paths — What They Actually Mean

- Paths are **directories** (or individual files) used as roots for a recursive walk (`rglob`).
- The walker collects candidates, then keeps only regular files whose suffix (case-insensitive) matches the language's extensions:
  - Python: `.py`
  - JavaScript: `.js`, `.jsx`, `.mjs`, `.cjs`
  - TypeScript: `.ts`, `.tsx`
  - Rust: `.rs`
- All internal paths are normalized to POSIX-style repo-relative strings (e.g. `src/foo/bar.py`) using `.as_posix()`. This keeps JSON and recommendations stable across Windows and POSIX.
- Defaults after `init`: `["src"]` for most languages; the Python sample includes `["src", "tests"]` because tests often contain the functions you actually want to measure risk for.
- **Why edit after init?** Your project layout may be:
  - A Rust workspace using `crates/`
  - A flat layout (use `["."]`)
  - A monorepo (list multiple: `["packages/web", "packages/api", "shared"]`)
  - Source under `lib/` or `app/`
- CLI can override without editing TOML: `crap4code scan crates/ --lang rust` or `crap4code scan . --lang python`.

See `src/crap4code/core/files.py:discover_source_files` for the exact walk + filter + (optional) git-changed intersection logic. Discovery returns `(files, warnings)` so git problems can be surfaced even on the "no files" path.

## Coverage Strategy (How the Tool Decides What to Do)

From root `README.md` and `config.py`:

- If `coverage_command` is set **and** `--report-only` is not used → delete stale_artifacts, run the command (platform shell), then ingest the report named by `coverage_report`.
- If no command runs but a report file exists at the configured path → just ingest it.
- If no trustworthy report can be loaded → coverage state = `indeterminate` for every function; CRAP = `N/A` (core guarantee — see concepts.md).

The `coverage_command` string is **never** interpreted by your interactive shell (pwsh/bash/etc.). It is passed verbatim to the platform default shell (`cmd.exe` via ComSpec on Windows; `/bin/sh` equivalent on POSIX). The long comment block generated by `init` explains quoting, `python -m` preference, `pwsh -Command` wrappers, env inheritance, and the `--report-only` safety valve. That block is the authoritative reference.

## Config Loading Behavior (for Agents and Debugging)

- Looks for `.crap4code.toml` (or `--config` value) relative to the cwd (treated as root).
- If the file is missing → synthesize a minimal enabled entry for every language the current registry advertises.
- If the file exists but is unparseable → use synthesized defaults + emit a warning (the scan continues).
- Unknown keys in a language section raise at load time (strict).
- Language sections that are absent or `enabled=false` are skipped.
- CLI `--lang` further narrows after config is loaded (and after the registry has done its tolerant load).

See `src/crap4code/core/config.py:load_project_config` and the warning paths in `cli.py:_scan`.

## Updating the Sample

Re-running `crap4code init --force` will overwrite with the current `sample_config_text()`. This is useful after a tool upgrade that improved the embedded comments. Your customizations (paths, specific report names, commands) will be lost — keep them in version control or re-apply after a force init.

## Minimal Working Example (Flat Python Project)

```toml
[scan]
default_paths = ["."]

[python]
paths = ["."]
coverage_report = "coverage.xml"
coverage_format = "coverage.py-xml"
```

Then: `crap4code scan --report-only`.

For more examples see the full text returned by `sample_config_text()` (run init and read the file, or open `src/crap4code/core/config.py`).
